# Deploying {{nombre_asistente}}

Generated by `ipsis deploy prepare` (profile `{{perfil}}`). This folder
holds everything the service needs: configuration, documents, index,
and avatars. Copy the whole folder to the server (VPS).

## 1. On the server

You need Docker with the `compose` plugin. Then, inside this folder:

```bash
cp .env.example .env               # and fill in IPSIS_ADMIN_TOKEN if you want /admin
sudo chown -R 10001:10001 config .ipsis   # the container does not run as root
docker compose --profile https up -d --build
```

- **HTTPS:** with the `https` profile, Caddy obtains and renews the
  certificate for `{{dominio}}`. First point the domain's DNS to the server's
  IP and open ports 80 and 443.
- **Without Caddy:** `docker compose up -d --build` exposes the assistant only
  on `127.0.0.1:8000`, for your own proxy.
- **Check:** `curl https://{{dominio}}/ready` returns 200 when everything is
  ready; otherwise `proyecto.bloqueante` says what is missing and which
  command fixes it.

The first build downloads the profile's models. After that the service does
not use the network.

## 2. On your website

Paste before `</body>`:

```html
{{snippet}}
```

And allow your site in the service (`cors_origins` in
`config/assistant.yaml`), for example with
`ipsis configure cors_origins=https://www.your-site.com` before preparing the
deployment.

## 3. The `/admin` panel

1. Generate a token: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
2. Put it in `.env` as `IPSIS_ADMIN_TOKEN=...`.
3. `docker compose --profile https up -d`.
4. Open `https://{{dominio}}/admin/panel` and paste the token.

In production `/admin` requires HTTPS. Without a token, the panel does not
exist.

## Changing configuration

In your original project, before preparing deployment:

```bash
ipsis configure cors_origins=https://www.your-site.com query_log.enabled=true
ipsis profile set medium
ipsis models download
ipsis profile show
ipsis snapshot-config --output reports/config-review.yaml
```

`configure` edits `config/assistant.yaml`. The models and the v2 budgets use
`config/engine.yaml`; merge this block with existing settings:

```yaml
profile_overrides:
  models:
    reranker: Horizon-Labs/multilingual-reranker-small
```

Precedence is profile, then `profile_overrides`. These settings are not an accuracy guarantee.

Evaluate in the original project, which contains the golden set (not copied here):

```bash
ipsis golden validate
ipsis evaluate --output reports/evaluation.json
ipsis benchmark --bank golden/bank/manifest.json --profiles light,medium --output reports/profiles
ipsis doctor
```

Full answers use the same criterion across profiles; QA span quality is separate
and not applicable without a reader. `evaluate` fails for wrong direct answers
or false `ok`.
`doctor` and `/ready` check operation, not answer accuracy.

After deployment, edit this folder's `config/assistant.yaml` or `config/engine.yaml`
and run `docker compose restart asistente`. To use the container's CLI, stop
the service first when Qdrant is local:

```bash
docker compose stop asistente
docker compose run --rm --no-deps asistente docker compose run --rm --no-deps asistente ipsis doctor
docker compose --profile https up -d
```

Corpus, chunking or dense-model changes require indexing, and golden validation.
Tone/avatar use `ipsis personality` or `config/personality.yaml`; widget settings use
`ipsis widget style` or `config/styles.yaml`.

## Updating

Medium uses e5-small + mMiniLM + mDeBERTa. Select
alternatives through `config/engine.yaml::profile_overrides.models` (`dense`,
`reranker`, `reader`), keeping `retrieval.model: null`. The image reads these
overrides when downloading models. Reindex and rebuild after changes with
`docker compose build --no-cache asistente`. In the source repository,
`python herramientas/evaluacion/general.py --download` runs document regression;
the real project's golden set remains necessary for answer evaluation.

- **Documents or configuration:** on your computer, run `ipsis load`,
  `ipsis index` and `ipsis deploy prepare` again; copy the folder and run
  `docker compose --profile https up -d --build`.
