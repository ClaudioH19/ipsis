# Deploying {{nombre_asistente}}

Generated by `ipsis desplegar preparar` (profile `{{perfil}}`). This folder
holds everything the service needs: configuration, documents, index,
calibration and avatars. Copy the whole folder to the server (VPS).

## 1. On the server

You need Docker with the `compose` plugin. Then, inside this folder:

```bash
cp .env.ejemplo .env               # and fill in IPSIS_ADMIN_TOKEN if you want /admin
sudo chown -R 10001:10001 config .ipsis   # the container does not run as root
docker compose --profile https up -d --build
```

- **HTTPS:** with the `https` profile, Caddy obtains and renews the
  certificate for `{{dominio}}`. First point the domain's DNS to the server's
  IP and open ports 80 and 443.
- **Without Caddy:** `docker compose up -d --build` exposes the assistant only
  on `127.0.0.1:8000`, for your own proxy.
- **Check:** `curl https://{{dominio}}/ready` returns 200 when everything is
  ready; otherwise `proyecto.bloqueante` says what is missing and which
  command fixes it.

The first build downloads the profile's models. After that the service does
not use the network.

## 2. On your website

Paste before `</body>`:

```html
{{snippet}}
```

And allow your site in the service (`cors_origins` in
`config/assistant.yaml`), for example with
`ipsis configurar cors_origins=https://www.your-site.com` before preparing the
deployment.

## 3. The `/admin` panel

1. Generate a token: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
2. Put it in `.env` as `IPSIS_ADMIN_TOKEN=...`.
3. `docker compose --profile https up -d`.
4. Open `https://{{dominio}}/admin/panel` and paste the token.

In production `/admin` requires HTTPS. Without a token, the panel does not
exist.

## Updating

- **Documents or configuration:** on your computer, run `ipsis cargar`,
  `ipsis indexar` and `ipsis desplegar preparar` again; copy the folder and run
  `docker compose --profile https up -d --build`.
